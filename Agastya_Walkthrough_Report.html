1. Executive Summary & Audit Overview

Agastya was developed for SIH Problem Statement 26085 to solve urban flood nowcasting and emergency vehicular routing around the Minto Bridge underpass in Central New Delhi. Prior to remediation, an extensive 46-feature audit of the codebase against the Technical Report revealed several critical bugs:

  • PySewer Key Mismatch: In pysewer_adapter.py, elevation and length were looked up via elevation_m and length_m while the graph stored them as elevation and length. This caused all 25 nodes to default to 215.0m elevation, flattening all hydraulic slopes to 0.002 and disabling downhill flow orientation.
  • Zero Rain Inconsistency: Choked manholes received an artificial +12.0 cm water depth on a completely dry day (rain = 0 mm/hr).
  • Conduit Throttling: An uncalibrated 0.025 inlet capture clamp artificially throttled Manning pipe flow conveyance.
  • Routing Blindspots: Submerged origins and destinations (>15 cm) were not detected, and edge-level flooding was unpenalized.
  • Offline Fallback Discrepancy: The frontend reverted to an 8-node mock topology instead of the true 25-node Minto Bridge catchment when the backend was offline.

All issues were resolved. The prototype now honestly represents its datasets, enforces conservation-aware hydrology, includes 24 automated unit and integration tests, executes with sub-10ms latency, and provides a deterministic 15-step demonstration for hackathon evaluation.

3. Key Bugs & Hydrologic/Mathematical Fixes

A. PySewer Key Mismatch Resolved

In pysewer_adapter.py, node elevation and edge length were read via data.get("elevation_m", 215.0) and data.get("length_m", 150.0). In graph_build.py, node attributes were stored as "elevation" and edge attributes as "length". Consequently, every node defaulted to 215.0m elevation, hydraulic slopes collapsed to 0.002, and downhill flow orientation failed.

Fix Applied: Supported dual-key access data.get("elevation", data.get("elevation_m", 215.0)) and data.get("length", data.get("length_m", 50.0)). Conduit edges now properly orient downhill towards the Minto Bridge outfall (210.5m), calculating real slopes and self-cleansing velocities.

B. Zero-Rain Hydrological Consistency

Previously, enabling choke mode during zero rainfall caused the engine to add +12.0 cm of water depth to the choked manhole on a completely dry day.

Fix Applied: Enforced strict dry-weather condition: if rain_mm_hr <= 0: return {node: 0.0 for node in G.nodes}. Zero rainfall now strictly yields 0.0 cm depth across all 25 nodes, even when manholes are marked as choked.

C. Dynamic Backwater Surcharge Propagation

The previous implementation applied a static +12 cm constant to blocked nodes without scaling or upstream propagation.

Fix Applied: Surcharge is now dynamically scaled with rainfall intensity and storm accumulation duration: $$\Delta d_{ ext{backwater}} = 12.0 imes \left( rac{I}{50} ight) imes \left( rac{t}{30} ight) \quad [ ext{cm}]$$ Upstream feeding neighbors draining into the choked conduit receive a dynamic backwater head increment (+5 cm baseline), labeled as a Prototype Heuristic Backwater Estimate.

D. Submerged Endpoint & Edge-Level Safe Routing

safe_route.py previously only removed intermediate flooded nodes; if the dispatch origin or target hospital itself was inundated, it allowed an ambulance to deploy into deep water.

Fix Applied: If origin or destination depth exceeds the 15 cm clearance threshold, pathfinding immediately halts with reachable: False and an explicit safety advisory. Connecting road edges where $\max(d_u, d_v) > 15 ext{ cm}$ are pruned from the traversal graph.
